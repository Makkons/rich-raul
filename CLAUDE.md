# Rich&Raul — вёрстка

## Сборка и деплой
- Исходники в `src/`, в git коммитится только собранная `app/` (см. `.gitignore`). Перед коммитом — `npm run backend`.
- Пуш в `main` = FTP-деплой на прод.
- Всё, что лежит в `src/img/**`, копируется в `app/img` и уходит в git — тяжёлые исходники туда не класть.

## Новости (news-details) — вёрстка «под БД»
Клиент вставляет в БД не страницу, а только тело новости — содержимое `.news-details__text`.
HTML старых новостей уже лежит в БД и не обновляется: существующие классы `theses*` нельзя переименовывать и менять их поведение — только добавлять новые модификаторы.

Новые новости — только на `theses theses--news`. Старые `theses--bulanova` / `theses--spring` / `--lookbook` / `--resort` — легаси, в новых новостях не использовать. `--news` объявлен в SCSS списком селекторов с `--bulanova` и `--spring` (`&--bulanova, &--news {…}`, `&--spring, &--news {…}`): стили общие, но менять их можно, только проверив и старые новости. То, что нужно только новым новостям, писать в отдельный блок `&--news`.

Структура:
- `src/news-details-<slug>.html` — страница-обёртка (копия любой существующей, меняется только include).
- `src/partials/news/<slug>.html` — breadcrumbs, `h1`, дата и тело новости.
- Картинки — `src/upload/demo/img/news/<slug>/` (задача `demo` сжимает их и делает `.webp`).
- HTML для клиента: `npm run news` → `news-db/news-details-<slug>.html` (типографированный фрагмент, папка не в git).
- Новые классы работают на проде только после деплоя `app/` — деплоить CSS до того, как клиент вставит HTML.

### Блоки (`src/partials/news/_blocks/`)
Фото вставляются только через блоки — они собирают `<picture>` с `@0.5x`/webp по соглашению. Эталон — `bilibin-code`.
Текст и кнопка пишутся обычной разметкой (см. ниже).

```html
<div class="theses theses--news theses--gap-60">
    @include('_blocks/hero.html', {"slug": "…", "src": "hero", "w": 2880, "h": 1625, "alt": "…"})
    @include('_blocks/photo.html', {"slug": "…", "src": "image-01", "w": 2000, "h": 3005, "size": "slim", "alt": "…", "link": "/catalog/…/", "caption": "…"})
    @include('_blocks/grid.html', {"slug": "…", "img1": "image-02-01", "img2": "image-02-02", "w": 1190, "h": 1591, "alt": "…", "link": "/catalog/…/", "caption": "…"})
</div>
```
- `photo.html`: `size` — не задан (≤ 690px) | `slim` (≤ 1000px, на узких экранах до края) | `full` (на всю ширину). `link`/`caption` — необязательная подпись-ссылка.
- `grid.html`: два фото в ряд, `w`/`h` общие (нужны только для пропорций). По умолчанию сетка на узких экранах выходит к краям экрана; `"clip": false` — оставить в контейнере.
- В блоках параметры подставляются как `@имя` регуляркой без границы слова: новый параметр не должен быть началом другого (`@src` ≠ `@srcset`) и не называть его `content` (зарезервировано).
- Блоки не видят параметров родителя — `slug` передаётся в каждый вызов.

### Разметка без блоков
- Текст: `div.theses__content.content.content--center > p.theses__text`; подзаголовок внутри абзаца: `<strong>…</strong><br><br>…`.
- Кнопка: `a.theses__button.button.button--outline > span.button__text`.

### Модификаторы
Нюансы конкретной новости закрывать общими модификаторами, а не модификатором под новость:
- `theses--gap-60` — отступ между блоками 60px (по умолчанию 100px).
- `theses__text--small` — текст 16px (по умолчанию 20px).
- `theses__picture--clip` — выход к краям экрана при ширине ≤ 1386px (hero, сетки, `slim`).

### Грабли
- Не ставить `loading="lazy"`: в `.theses--news` (и `--bulanova`) ширина блока считается из натурального размера картинки, незагруженная lazy-картинка схлопывается в 0 и так и не грузится.
- Размеры картинок: на всю ширину — 2880px, `slim` — 2000px, в сетке — 1190px; `@0.5x` — вдвое меньше. Только `.jpg`.
